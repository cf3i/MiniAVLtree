# REFLECT-1-html-avl-visualizer

## 1. 本次遇到的问题

- 仓库原本只有单文件 C++ 示例，没有任何前端目录或构建系统，因此必须把可视化功能收敛成零依赖静态页面，而不能引入过重工程结构。
- 需要让浏览器页面具备可执行验收，而不仅是“看起来能用”；为此页面脚本被设计成浏览器 / Node 双用模块，让 `issue_test` 可以直接验证 AVL 插入、旋转和布局逻辑。
- `gh pr create` 首次尝试时，命令里的 Markdown 反引号被 shell 解释，导致命令失败；后续改用 `--body-file` 规避了这个问题。

## 2. 是否有新 wisdom 条目

- 是。
- 原因：对“前端页面 + 无构建系统 + 仍需可执行回归”的仓库，浏览器 / Node 双用脚本是高复用模式，既能支撑页面交互，也能让 issue_test 直接验证核心逻辑。

## 3. 是否有新 antipattern 条目

- 是。
- 原因：在 shell 中直接把带反引号的 Markdown 文本塞给 `gh pr create --body`，容易触发命令替换，属于可重复踩坑的失败模式。
